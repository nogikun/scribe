## 評価 2: 独立した声紋モデルによる一貫性 (Nemotron)

Nemotron とは別のモデル (3D-Speaker CAM++) で 2 秒以上の 328 ターンの声紋を計算し、話者ごとの重心と比較。

- **全ターンの 100% が自分の話者の重心に最も近い** (他人に誤帰属された形跡なし)。
- 話者間の重心類似度は最大 0.59 (SPEAKER_00 と 02)、他は 0.13〜0.52。同一人物が 2 つに分かれた形跡なし。
- 注意: SPEAKER_04/05 は 2 秒以上のターンが 1 つずつしかなく、この検査は実質無効。

## 評価 3: sherpa-onnx との比較 (閾値スイープ)

Nemotron 結果を参照として、sherpa の各閾値を 100ms フレーム単位で比較。

| threshold | 話者数 | 多対一一致率 | 一対一一致率 (DER 的) |
|---|---|---|---|
| 0.5 | 135 | 96.5% | — |
| 0.8 | 41 | 96.3% | — |
| 0.9 | 25 | 95.8% | 87.4% |
| **1.0** | **14** | 95.1% | **88.1%** |
| 1.1 | 8 | 89.9% | 89.1% |
| 1.3 | 1 | 55.0% | 55.0% |

- sherpa は話者を「混ぜる」のではなく「細切れにする」傾向 (多対一一致率は常に高い)。閾値 0.5 では命名すべき話者が 135 人になり Human-in-the-loop が破綻する。
- 2 声の短い音声 (TTS) では 1.0 以下で正しく 2 話者、1.05 以上で 1 人に統合されてしまう。
- **既定値は 1.0** (`--cluster-threshold` で調整可)。過分割は同じ名前を付ければ書き出し時に統合できるが、別人の統合は後から直せないため、分割寄りに倒した。2 本の音声でしか較正していない点に注意。
- Nemotron と sherpa の結果が高い一致を示すことは、互いに独立な手法の相互検証にもなっている。

## 見つかった問題と対処

| 問題 | 対処 |
|---|---|
| sherpa 既定閾値 0.5 で 135 話者に過分割 | 既定 1.0 に変更、CLI で調整可能に |
| Nemotron の特徴抽出に `librosa` が必要 | `nemotron` extra に追加 |
| faster-whisper が CUDA で `cublas64_12.dll` 不足 | cu128 torch 同梱の DLL を検索パスに追加 → GPU で 4.4 倍速 |
| 話者 ID が 100 を超えると文字列順で並ぶ | 数値順に修正 |
| 進捗が出ず止まって見える | 全ステージに進捗バー / 経過時間表示を追加 |

## 残る課題

- **話者交代境界の数百 ms の揺れ**: 例「中村君覚えてるっけ / 覚えてます」(167〜171 秒)。Whisper が同じ語を 2 か所に出力しており、ASR のタイムスタンプ精度が律速。話者分離側の誤りとは断定できない。
- **Whisper small の誤認識** (例「画面給与ください」= 画面共有)。話者分離とは別問題。精度が必要なら `--model medium` 等を試す。
- **Nemotron は最大 8 話者**。9 人以上の会議では sherpa (閾値調整) か pyannote を使う。
- **Nemotron はメモリが音声長に比例** (49 分で CPU 3.4GB)。2 時間超を CPU 8GB で処理する場合はストリーミング推論への切替が必要。
- **pyannote は未評価** (HF_TOKEN を設定すれば同じ手順で比較可能)。
- 正解ラベルが無いため絶対的な DER は未測定。正解付きの会議が 1 本あれば同じスクリプトで DER を出せる。
